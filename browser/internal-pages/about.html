The THAAW Manifesto & Origin

The name THAAW is rooted in the Kashmiri word تھاو (Thaaw), translating directly to an imperative: “Stop.” Or more precisely: “Halt right here.”

The modern web was architected with noble intentions: universal access to information, open communication, and distributed human knowledge. However, over the past two decades, commercial pressures transformed the browser from a neutral agent of the user into an active surveillance vector. Browsers today report every click, keystroke, mouse trajectory, and geographic coordinate back to centralized advertising exchanges. They run dozens of background telemetry pings before the requested page even finishes painting its first frame.

THAAW rejects this paradigm. When you launch THAAW, the browser acts solely on your behalf. Its mandate is simple and uncompromising:

Zero Remote Telemetry
Not a single byte of usage statistics, browsing history, crash traces, or performance analytics ever leaves your computer. No pings, no beacons, no Google analytics, no Firebase tracking.
In-Process Stop Interceptor
Trackers and intrusive ad networks are aborted at the pre-socket network phase. No sockets are allocated, no DNS queries are executed, and no payload bytes are downloaded.
Isolated Profile Partitions
Every workspace profile operates in a strictly isolated session partition. Cookies, local storage, service workers, and caches cannot cross profile boundaries under any circumstances.
Encrypted Local Vault
Your passwords and sensitive credentials are encrypted locally using PBKDF2-SHA256 and authenticated AES-256-GCM. Plaintext never touches your storage drive.

The WebContentsView Compositor & Snapshot Layer

In Electron, child WebContentsView instances sit on top of the parent window's base DOM at an operating-system compositor level. When a browser UI requires dropdowns, menus, or modals that overlap the webpage area, standard webviews intercept all mouse clicks, rendering HTML popovers unclickable or causing the tab to blank out if hidden.

THAAW solves this with an innovative Dynamic Snapshot Compositor Layer:

  1. When any popover or modal opens (e.g. Downloads popover, Profile switcher, Main menu, Command palette), tabManager.setModalOpen(true) captures a hardware-accelerated bitmap snapshot of the active tab view via active.view.webContents.capturePage() in under 3 milliseconds.
  2. The snapshot bitmap is broadcast to the chrome UI and painted to the #tabSnapshotLayer background immediately.
  3. The native view is temporarily set to setVisible(false), transferring full OS-level input focus directly to the chrome UI popovers while the user visually perceives zero change or interruption.
  4. When the popover or modal is dismissed, setVisible(true) is immediately restored, and the snapshot layer is cleared.

Security & Privacy Deep Dive

THAAW operates on a verifiable defense-in-depth model. We make no unsubstantiated claims of being impervious to zero-day vulnerabilities; instead, we systematically minimize attack surfaces, isolate failure domains, and eliminate vectors of passive exploitation.

Pre-Socket Request Blocking
All outgoing HTTP/HTTPS requests pass through TrackerBlocker.shouldBlockRequest() before TCP socket creation or TLS handshakes occur. Telemetry servers receive zero network communication.
Strict Origin Referrer Trimming
Outgoing Referer request headers are automatically stripped to origin only (https://example.com/ instead of full URL paths with tracking parameters and session tokens).
Cosmetic Element Hiding
Injected stylesheets seamlessly collapse empty advertisement containers, tracking iframes, and sponsored video overlays so web layouts render cleanly without visual clutter.
YouTube Ad Fast-Forwarding
Automated video player monitors detect in-stream promotional ads, fast-forward through playback segments at 16x speed, and trigger instant programmatic skip clicks on user behalf.
// Core Request Interception logic in browser/privacy/tracker-blocker.ts public shouldBlockRequest(url: string, origin?: string): { block: boolean; rule?: string } { if (!this.shieldActive) return { block: false }; const hostname = new URL(url).hostname.toLowerCase(); // Pre-socket block matching against curated ad networks, trackers, and telemetry if (this.blockedDomains.has(hostname) || this.adBlocker.isAdDomain(hostname)) { this.recordBlocked(hostname, origin); return { block: true, rule: 'tracker-or-ad-domain' }; } return { block: false }; }

The 4-W Permission Framework

Standard web browsers present ambiguous permission dialogs (e.g. “example.com wants to know your location”) that fail to convey why a permission was requested or how long the grant persists. THAAW implements the 4-W Architecture:

Dimension Verification Principle THAAW Enforcement Behavior
WHO Cryptographic Origin & Certificate Identity Explicitly verifies the fully qualified domain name, protocol, and port. Subdomains are not automatically trusted based on parent domain approvals.
WHAT Precise Resource Capability Dissects requests into explicit hardware and data categories: Camera, Microphone, Geolocation, Notifications, Clipboard Read/Write, MIDI, or Screen Capture.
WHY Contextual Justification Derivation Evaluates whether the request was triggered by direct user gesture (e.g. clicking a call button) or background script injection. Passive background requests are denied by default.
WHERE / WHEN Granular Duration Scope Provides three distinct user decisions: Allow for This Visit (revoked immediately on tab close), Allow Always (persisted per-profile), and Deny (permanent block).

Profile Isolation & Multi-Identity Workspaces

THAAW treats each user profile as a completely isolated container. Whether separating Personal, Work, Developer, or Guest activities, profiles never share state:

  • Storage Partitioning: Every profile is mapped to a dedicated partition name (persist:thaaw_profile_<id>). Cookies, IndexedDB, local storage, WebSQL, and CacheStorage are physically separated on disk.
  • Zero Cross-Contamination: Logging into an account in the Personal profile cannot be detected by trackers or authentication scripts running in the Work or Developer profiles.
  • Guest Mode Self-Destruction: Guest profiles run in ephemeral partitions. Upon closing the guest session, all associated browsing data, cookies, and cached objects are securely purged from memory.
  • Dynamic Profile Switcher: Switch seamlessly between profiles from the top toolbar without quitting the browser or reloading open tabs in other windows.

Cryptographic Password Vault

The built-in THAAW Password Vault stores website credentials locally with zero cloud dependencies, eliminating data breach risks associated with remote password synchronization services:

PBKDF2-SHA256 Derivation
Master encryption keys are derived using PBKDF2 with SHA-256 and 100,000 computation iterations, rendering brute-force dictionary attacks computationally infeasible.
AES-256-GCM Encryption
All stored credentials (usernames, passwords, and metadata) are encrypted with AES-256 in Galois/Counter Mode (GCM), providing authenticated encryption with integrity tags.
Zero Plaintext Disk Writes
Passwords exist in plaintext strictly in temporary memory during explicit user autofill or review actions. Storage files contain only ciphertext and cryptographic salts.
Instant Memory Sanitization
When credentials are deleted or when the vault is locked, in-memory buffers are overwritten with zero-bytes to protect against memory scraping attacks.

Frequently Asked Questions (FAQ)

How does THAAW differ from browsers like Brave, Chrome, or Firefox?
Mainstream commercial browsers incorporate telemetry, cloud-synced account systems, and sponsored features by design. Brave operates an ad network (Brave Rewards) and cryptocurrency services. Google Chrome is built by the world's largest advertising conglomerate. Firefox includes Pocket recommendations and Mozilla telemetry pings. THAAW is entirely non-commercial: zero advertising programs, zero cryptocurrency, zero sponsored shortcuts, zero telemetry, and 100% local cryptographic processing.
Does THAAW send any data to remote servers when I search?
No. The omnibox does not send keystrokes to remote servers for suggestions. Suggestions are generated entirely from your local browsing history and bookmarks. When you submit a search query, it is sent directly to your chosen default search engine (DuckDuckGo by default, or Google, Bing, Brave, or a custom search URL).
How does the built-in ad blocker function without browser extensions?
THAAW integrates the ad and tracker blocking engine directly into the Electron session request pipeline (webRequest.onBeforeRequest). Because filtering occurs at the native network layer before HTTP sockets or TLS handshakes are initialized, it consumes drastically less CPU and memory than JavaScript-based browser extensions like uBlock Origin.
Can websites detect that I am using THAAW?
Websites see a standardized Chromium User-Agent header matching standard Linux desktop browsers. THAAW avoids leaking unique browser identifiers, preventing fingerprinting scripts from singling out your machine.
Where is my browsing data, history, and vault stored?
All user data resides strictly on your local filesystem in your user directory: ~/.config/thaaw-browser/. You can back up, inspect, or delete this directory at any time. No cloud backups are ever initiated.
Why is there no audio crackling on Linux video playback?
Chromium defaults to a 512-sample audio buffer, which frequently underflows on Linux distributions using PipeWire or PulseAudio with Bluetooth sinks. Furthermore, Chromium's AudioServiceSandbox prevents the audio worker thread from obtaining real-time priority via RTKit. THAAW configures a 2048-sample buffer and disables the thread scheduling block, guaranteeing smooth, jitter-free audio reproduction.
Is THAAW open-source?
Yes. THAAW is licensed under the permissive BSD 3-Clause License. The complete source code is auditable, transparent, and forkable without proprietary encumbrances.
